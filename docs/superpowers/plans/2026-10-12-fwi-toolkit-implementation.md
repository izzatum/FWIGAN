# FWI toolkit implementation

Goal: deliver a reusable, efficient research workflow for legacy FWIGAN and a conventional velocity-only FWI baseline, with reliable restart and both notebook and command-line clients.

Spec: `docs/superpowers/specs/2026-10-12-fwi-research-toolkit-proposal.md` (approved). This iteration implements phases 1–4 and the gradient-isolation optimization from phase 6. Frequency continuation, joint statistical noise/source constraints, a different critic distribution, and a modern DeepWave backend remain separate method revisions. Keep the validated legacy solver while changing architecture.

Architecture: dataclass contracts and configuration; an injected acoustic-forward adapter; PyTorch modules owning inversion parameters; two explicit optimization strategies; one experiment lifecycle and snapshot format. Avoid registries, service locators, and unused extension points.

Stack: Python 3.10, PyTorch 1.13.1, DeepWave 0.0.9, NumPy 1.23.5, SciPy 1.10.1, PyYAML, pytest. The validated environment is `/workspace/.venvs/fwigan/bin/python`; use two CPU threads for bounded integration tests. Installation must install Torch before building DeepWave without build isolation.

## Global constraints

- Work in the existing isolated cloud checkout `/workspace/FWIGAN`, branch `work`. Preserve existing models and license. No new worktree, pushes, merges, or full Marmousi training.
- Canonical velocity `[nz,nx]`, source `[shots,sources,time]`, observations `[shots,receivers,time]`; coordinates `[shots,points,2]` in physical metres ordered `[z,x]`, `dt` in seconds. Shared source has one shot and is explicitly broadcast.
- The forward model returns deterministic raw-amplitude float32 traces and preserves velocity/source gradients. Legacy preprocessing is `trace / (abs(max_over_time(trace)) + 1e-10)`; do not silently replace it with absolute-maximum normalization.
- Legacy critic consumes `[1,shot_group,time,receivers]`. Validate its geometry, including the five pooling operations and fixed shot-group size, before training. Preserve the shot-stack distribution and strided batching of the original notebooks.
- Legacy clean/noisy configurations keep Adam groups (velocity LR 5, source LR .001, sigma LR .01 only when enabled, betas .5/.9); critic LR .001, same betas; StepLR periods 150/100 and gamma .5; loss GP weight 10, critic drift .001, value clips velocity 1000 and critic 1e6. Do not change the solver or scientific objective during extraction.
- Critic steps must detach predicted traces and physical steps must freeze critic weights while retaining input gradients. Reuse one wave solve per adversarial batch. Do not keep unnecessary graphs across critic cycles. CUDA AMP is explicit, CPU AMP disabled, physics kept float32. Track skipped AMP optimizer steps; schedulers must not advance an optimizer that has never stepped.
- Dataset and run files must be CPU-portable. All enabled/frozen physical quantities belong to module state; restore each named optimizer group's LR, critic, scheduler, scaler, next epoch/batch, metrics, observations, Python/NumPy/Torch/CUDA RNG, resolved config, data fingerprint, and schema. Write snapshots atomically. Resume restores the same run; warm start initializes selected physical tensors in a new run.
- Conventional FWI uses raw-amplitude data and fixed known source, no trainable sigma/source. Use bounded velocity by projection after an Adam step. Include optional spatial regularization. Normalize batch residual sums by the full dataset size and accumulate before one update, so incomplete final batches and full-shot gradients agree.
- No truth model is required for inversion of an observation artifact. Reject nonfinite/wrong-shape data, invalid acquisition, unsupported configs, incompatible snapshots, and unsafe artifact overwrites with clear errors.
- Tests establish reference traces/losses/gradients, update isolation, full-shot versus batched gradients, a small FWI data-fit improvement, clean/noisy interruption equivalence, CLI runs, and CPU-portable artifacts. Use real DeepWave for numerical integration checks; avoid tests that mirror trivial implementation.
- Measure performance after warmup, use CUDA synchronization for timings, compare equivalent work, and record peak GPU allocation and wave-solver/adjoint counts. Timing results are artifacts, not flaky CI assertions. Never claim a full-scale speedup from tiny data.

### Task 2: Efficient inversion strategies and numerical checks

Interfaces to produce:
- `LegacyCritic(shots, nt, receivers)` preserves original layers, names and initialization order where possible; exposes geometry validation and canonical-data input adaptation.
- `FWIGANStrategy(parameters, forward, data, config, observed=None)` owns critic, physical/critic Adam optimizers, schedulers and CUDA scalers. `step(batch_indices)->dict` performs original number of critic cycles and one physical update; returns finite scalar metrics and actual/skipped update counts. `.finish_epoch()` steps only appropriate schedulers. `.state_dict()` / `.load_state_dict()` restores all nonphysical strategy state. `.parameters` is the registered physical module. Set gradients to None instead of allocating/filling zeros. Aggregate losses on-device before host metric transfer. No physics autocast.

Fixed known source, no sigma. Both methods use the same forward protocol.
- Named construction function `build_strategy(parameters, forward, data, config)` uses a simple explicit conditional.
