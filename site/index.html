What is FWIGAN?

FWIGAN is a Python research toolkit for 2D acoustic full-waveform inversion. It provides conventional FWI and adversarial FWIGAN with shared configuration, DeepWave wave physics, evaluation, and checkpoint/resume workflows.

How do FWI and FWIGAN differ?

Conventional FWI fits raw observed waveforms with a least-squares objective and a known fixed source. FWIGAN uses an adversarial critic with the original per-trace normalization and can fit the source waveform; its noisy variant also fits a noise parameter. The methods have different objectives, so a lower training loss does not by itself establish a better velocity model.

How does FWIGAN use PyTorch?

PyTorch supplies the trainable tensors, critic, automatic differentiation, and optimizers. The pinned DeepWave 0.0.9 backend computes acoustic wave propagation. This repository uses a legacy stack: Python 3.10 and PyTorch 1.13.1, with Torch installed before compiling DeepWave.

How do I run a small example?

Run the tiny CPU preset from the repository root. The command prints a new run directory.

fwigan invert --config configs/tiny-fwigan.yaml --output-root runs --max-batches 2

Use configs/tiny-fwigan-noisy.yaml for noisy FWIGAN or configs/tiny-fwi.yaml for conventional FWI. Full Marmousi presets are available in configs/marmousi-*.yaml.

Source: README installation and quick start.

Does FWIGAN require a GPU?

No. The tiny examples run on CPU. CUDA is optional and requires a compatible PyTorch/DeepWave build; the documented GPU stack uses Torch 1.13.1+cu117 and a CUDA 11.7 toolchain. The CLI does not allocate a GPU. Validate compatibility on the actual device using the CUDA setup and integration instructions.

Can I resume a FWIGAN run?

Yes. Resume a package run from its saved checkpoint and evaluate its run directory. Replace <run-id> with the directory printed by the inversion command:

fwigan resume runs/<run-id>/checkpoint.pt --device cpu
fwigan evaluate runs/<run-id>

Keep run.json, config.json, and observations.pt with the checkpoint. Resume restores the same run’s physical state, critic, optimizers, schedules, progress, and random states. Only load trusted checkpoint files.

The public 120-epoch evidence bundle omits the large full resumable checkpoint, so it cannot resume that exact A40 run. See the checkpoint and warm-start documentation and the run’s artifact limits.
